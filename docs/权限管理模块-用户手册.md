# starAItable 权限管理系统 · 用户手册

> 面向系统管理员与最终用户。配套：`权限管理模块-API规范.md`（开发者）、`权限管理模块-故障排除.md`（诊断）、`权限管理模块-部署运维.md`（上线/SLA）。

## 1. 角色说明

### 1.1 平台账户角色

| 角色 | 说明 |
|---|---|
| `admin` | 平台管理员：全部管理权限，可管理用户/角色/权限/审计/系统设置 |
| `member` | 普通成员：可访问被授予的功能，可提交权限申请 |

### 1.2 职能角色（业务角色）

由管理员创建，如「组织管理员」「部门管理员」「报表员」。支持：

- **层级继承**：子角色自动继承父角色权限（如「部门管理员」继承「组织管理员」的查看权限）。
- **负向权限**：`deny:<权限>` 显式拒绝，覆盖祖先的允许。
- **双层权限**：用户可直接被授予/拒绝某个权限点，覆盖角色继承结果。

## 3. 常见任务（分步说明）

### 3.1 创建角色（一键式）

1. 进入「角色权限」→ 点击 **新建角色**。
2. 填写角色名称、代码（英文唯一标识）、描述。
3. 勾选权限点；如需负向权限，在权限点代码前加 `deny:`（如 `deny:users.manage`）。
4. 选择父角色（可选）实现继承。
5. 点击 **保存**。

> 快捷方式：使用权限模板（见 3.4），一键创建带标准权限的角色。

### 3.2 为用户分配角色

1. 进入「用户管理」→ 搜索用户 → 点击用户名打开详情。
2. 在「职能角色授权」卡片勾选角色。
3. 点击 **保存授权**。

### 3.3 设置用户直接权限（双层权限）

1. 打开用户详情 → 找到「用户级直接权限」卡片。
2. 从权限目录选择权限点，选择效果 **允许** 或 **拒绝**，点击添加。
3. 移除时点击条目右侧的删除按钮。

> 冲突解决：**拒绝优先**；直接权限优先于角色继承。

### 3.4 使用权限模板

1. 进入「角色权限」→「权限模板」标签。
2. 查看模板列表与当前版本。
3. 点击 **应用** → 输入角色代码与名称 → 一键创建角色。
4. 点击 **版本历史** 查看改版记录；管理员可创建新版本。

### 3.5 提交权限申请

1. 在需要权限的功能页面点击「申请权限」。
2. 选择权限点、填写理由。
3. 提交后进入审批流，可在「我的申请」查看状态。

### 3.6 审批权限申请

1. 进入「权限审批」→ 查看待办列表。
2. 查看申请详情（申请人、权限点、理由、关联审批链）。
3. 点击 **同意** 或 **拒绝**，填写审批意见。

> 多级审批：第一级审批通过后自动流转到下一级；超过升级时限（默认 24h）自动升级到更高级审批人。

### 3.7 启用 MFA

1. 进入「系统设置」→「MFA」。
2. 选择方式：
   - **邮箱验证码**：输入邮箱，点击发送验证码，填写后启用。
   - **认证器 App**：扫描二维码或手动输入 Base32 密钥到 Google Authenticator / Microsoft Authenticator，输入 6 位动态码确认。
3. 启用后，每次登录需完成第二步验证。

### 3.8 配置 IP 访问规则

1. 进入「系统设置」→「IP 访问规则」。
2. 添加规则：选择类型（允许/拒绝）、填写 IP（支持精确 IP、CIDR、通配符）。
3. 切换模式：
   - **黑名单模式**：仅拒绝命中 deny 规则的 IP。
   - **白名单模式**：仅允许命中 allow 规则的 IP，其余拒绝。

> 修改前请确保当前管理 IP 已加入白名单，避免把自己锁在门外。

### 3.9 配置 SSO

1. 进入「系统设置」→「SSO」。
2. 选择提供商（OAuth2/OIDC 或 SAML 2.0）。
3. 填写客户端 ID、客户端密钥、授权端点、令牌端点、用户信息端点（OIDC）；或上传 SAML 元数据 XML。
4. 保存后用户可通过「使用 SSO 登录」入口登录。

### 3.10 校验审计完整性

1. 进入「安全审计」→ 点击 **校验链完整性**。
2. 系统重新计算每条记录的哈希并与链上值比对。
3. 结果 `通过` 表示审计日志未被篡改；`失败` 会标出第一条被破坏的记录。

## 4. 审批链与升级

### 4.1 审批链模板

管理员可在「权限审批」→「审批链管理」中配置：

- 业务类型（如 `report.manage`）
- 审批人序列（一级、二级……）
- 升级时限（默认 24 小时）
- 通知方式（站内信/邮件）

### 4.2 升级机制

- 当前级审批人在时限内未处理 → 自动升级到下一级。
- 升级时通知原审批人与升级审批人。
- 审批链被撤销/失效时，待办自动通知申请人。

### 4.3 撤销

申请人可在审批完成前撤销申请；已通过的授权由管理员在用户详情中收回。

## 5. FAQ

**Q: 为什么用户有角色但无法访问某功能？**
A: 可能被负向权限 `deny:` 覆盖，或组织作用域未包含该资源。在用户详情的「权限解析」中查看来源。

**Q: 修改角色权限后多久生效？**
A: 进程内缓存即时失效；外部系统通过同步水印轮询，默认 60 秒内收敛（SLA 5 分钟）。

**Q: 忘记密码怎么办？**
A: 联系平台管理员重置。管理员在用户管理中选择「重置密码」。

**Q: 认证器丢失，MFA 无法登录？**
A: 联系管理员在「系统设置」中为用户解除 MFA 绑定，然后重新绑定。

**Q: 审计日志可以删除吗？**
A: 不可以。审计日志受触发器保护且哈希链校验任何篡改。仅合规要求的留存期满后按流程归档。

## 6. 最佳实践

1. **最小权限**：角色只授必需权限，优先使用模板。
2. **负向权限慎用**：`deny:` 优先于一切 allow，排查问题成本高，尽量通过角色拆分实现隔离。
3. **变更留痕**：敏感授权操作建议走审批流，自动写入审计。
4. **白名单模式先在测试环境验证**：避免误锁生产 IP。
