## 1. 角色与职责总览

### 1.1 平台账户角色

| 角色 | 说明 |
|---|---|
| `admin` | 平台管理员：拥有全部管理权限，可管理用户、角色、权限、审计、系统设置 |
| `member` | 普通成员：可访问被授予的功能，可提交权限申请 |

### 1.2 职能角色（业务角色）

由管理员创建的业务角色，例如「组织管理员」「部门管理员」「报表员」。支持以下特性：

- **层级继承**：子角色自动继承父角色权限。
- **负向权限**：`deny:<权限>` 显式拒绝，覆盖祖先的允许。
- **双层权限**：用户可直接被授予/拒绝某个权限点，覆盖角色继承结果。

### 1.3 管理员核心职责

- 用户生命周期管理（创建、禁用、重置密码、删除）
- 角色与权限配置（角色矩阵、权限模板、直接授权）
- 权限审批与审计链维护
- 系统参数、MFA、IP 规则、SSO 配置
- 数据备份与恢复演练
- 积分规则配置与充值/贡献审核
- AI 运行时与模型管理

## 2. 登录与首次配置

### 2.1 登录管理后台

1. 启动服务端（默认 `http://localhost:5100`）。
2. 浏览器打开管理端 `/admin.html`。
3. 使用管理员账号登录（首次部署见下文「提升首个账号为管理员」）。

### 2.2 提升首个账号为管理员

首次部署时注册的账号默认为 `member`，需手动提升：

```bash
# 进入 SQLite（默认数据目录见 info --json）
sqlite3 data/app.db "UPDATE users SET role='admin' WHERE id='<你的用户ID>';"
```

> ⚠️ **重要**：修改后必须**重新登录**，JWT 令牌内嵌角色，旧令牌不会自动刷新。

### 2.3 首次部署 Checklist

- [ ] 设置 `JWT_SECRET` 环境变量（生产必填）
- [ ] 确认 `DATABASE_PATH` 指向正确数据库
- [ ] 反向代理后设置 `TRUST_PROXY=1`
- [ ] 运行 `dotnet run --project src/LocalServe.Cli -- selftest` 完成 14 项自检
- [ ] 注册首个账号并提升为 admin
- [ ] 配置备份策略（`BACKUP_INTERVAL_HOURS` / `BACKUP_KEEP`）

## 3. 用户管理

### 3.1 创建用户

1. 进入管理端「用户管理」。
2. 点击 **新建用户**。
3. 填写用户名、昵称、邮箱、初始密码（或由系统生成）。
4. 选择初始角色（可选）。
5. 点击 **保存**。

> 说明：用户也可通过工作台登录页自助注册，注册后默认为 `member`。

### 3.2 为用户分配角色

1. 进入「用户管理」→ 搜索用户 → 点击用户名打开详情。
2. 在「职能角色授权」卡片勾选角色。
3. 点击 **保存授权**。

### 3.3 设置用户直接权限（双层权限）

1. 打开用户详情 → 找到「用户级直接权限」卡片。
2. 从权限目录选择权限点，选择效果 **允许** 或 **拒绝**，点击添加。
3. 移除时点击条目右侧的删除按钮。

> **冲突解决原则**：拒绝优先；直接权限优先于角色继承。

### 3.4 重置密码

1. 进入「用户管理」→ 找到目标用户。
2. 点击 **重置密码**。
3. 设置新密码（满足复杂度要求：≥8 位，含大小写/数字/符号）。
4. 用户下次登录需使用新密码。

### 3.5 禁用 / 删除用户

1. 打开用户详情。
2. 点击 **禁用**（保留数据，禁止登录）或 **删除**（软删除，不可恢复）。
3. 确认操作（删除属高风险操作，需二次确认）。

> ⚠️ **注意**：删除用户为不可逆操作，建议先禁用并观察一段时间。

### 3.6 批量操作

用户管理支持批量选择用户后执行：批量分配角色、批量禁用、批量启用。

## 4. 角色与权限分配

### 4.1 创建角色（一键式）

1. 进入「角色权限」→ 点击 **新建角色**。
2. 填写角色名称、代码（英文唯一标识）、描述。
3. 勾选权限点；如需负向权限，在权限点代码前加 `deny:`（如 `deny:users.manage`）。
4. 选择父角色（可选）实现继承。
5. 点击 **保存**。

### 4.2 使用权限模板

1. 进入「角色权限」→「权限模板」标签。
2. 查看模板列表与当前版本。
3. 点击 **应用** → 输入角色代码与名称 → 一键创建角色。
4. 点击 **版本历史** 查看改版记录；管理员可创建新版本。

### 4.3 权限矩阵与可视化

「角色权限」页提供权限矩阵视图，可直观查看每个角色对每个权限点的允许/拒绝状态；继承树视图展示角色层级关系。

### 4.4 权限变更生效时间

- 进程内缓存即时失效。
- 外部系统通过同步水印轮询，默认 60 秒内收敛（SLA 5 分钟）。

## 5. 权限审批与审计

### 5.1 审批链配置

1. 进入「权限审批」→「审批链管理」。
2. 点击 **新建审批链**。
3. 配置：
   - 业务类型（如 `report.manage`）
   - 审批人序列（一级、二级……）
   - 升级时限（默认 24 小时）
   - 通知方式（站内信/邮件）
4. 点击 **保存**。

### 5.2 审批权限申请

1. 进入「权限审批」→ 查看待办列表。
2. 查看申请详情（申请人、权限点、理由、关联审批链）。
3. 点击 **同意** 或 **拒绝**，填写审批意见。

> **升级机制**：当前级审批人在时限内未处理 → 自动升级到下一级；升级时通知原审批人与升级审批人。

### 5.3 校验审计完整性

1. 进入「安全审计」→ 点击 **校验链完整性**。
2. 系统重新计算每条记录的哈希并与链上值比对。
3. 结果 `通过` 表示审计日志未被篡改；`失败` 会标出第一条被破坏的记录。

> ⚠️ **注意**：审计日志受触发器保护且哈希链校验任何篡改，**不可手动删除**。仅合规留存期满后按流程归档。

### 5.4 访问统计

「访问统计」页提供登录/操作统计、PV/UV/DAU/错误率/耗时/时段分布等运营指标。

## 6. 系统配置

### 6.1 启用 MFA

1. 进入「系统设置」→「MFA」。
2. 选择方式：
   - **邮箱验证码**：输入邮箱，点击发送验证码，填写后启用。
   - **认证器 App**：扫描二维码或手动输入 Base32 密钥到 Google Authenticator / Microsoft Authenticator，输入 6 位动态码确认。
3. 启用后，每次登录需完成第二步验证。

### 6.2 配置 IP 访问规则

1. 进入「系统设置」→「IP 访问规则」。
2. 添加规则：选择类型（允许/拒绝）、填写 IP（支持精确 IP、CIDR、通配符）。
3. 切换模式：
   - **黑名单模式**：仅拒绝命中 deny 规则的 IP。
   - **白名单模式**：仅允许命中 allow 规则的 IP，其余拒绝。

> ⚠️ **注意**：修改前请确保当前管理 IP 已加入白名单，避免把自己锁在门外。

### 6.3 配置 SSO

1. 进入「系统设置」→「SSO」。
2. 选择提供商（OAuth2/OIDC 或 SAML 2.0）。
3. 填写客户端 ID、客户端密钥、授权端点、令牌端点、用户信息端点（OIDC）；或上传 SAML 元数据 XML。
4. 保存后用户可通过「使用 SSO 登录」入口登录。

### 6.4 系统参数（服务端环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 5100 | 监听端口 |
| `JWT_SECRET` | 开发缺省随机 | **生产必填** |
| `DATABASE_PATH` | 数据目录 | SQLite 路径 |
| `TRUST_PROXY` | 0 | =1 时限流器采信 `X-Forwarded-For` |
| `RATE_MAX` | 600 | API 每分钟请求上限 |
| `BACKUP_INTERVAL_HOURS` | 24 | 定时备份间隔（0 关闭） |
| `BACKUP_KEEP` | 7 | 备份保留份数 |
| `AI_USAGE_RETENTION_DAYS` | 90 | AI 用量保留天数（<=0 永久） |

## 7. 数据备份与恢复

### 7.1 备份策略

| 级别 | 频率 | 方式 |
|---|---|---|
| 全量 | 每日 | `VACUUM INTO` 一致性快照（服务端自动执行） |
| 增量 | 每 6 小时 | 复制 WAL 文件（配合全量恢复） |
| 审计归档 | 每月 | 导出审计日志到只读归档 |

### 7.2 手工备份

```bash
# 执行备份（保留最近 7 份）
dotnet run --project src/LocalServe.Cli -- backup run --keep 7

# 查看备份列表
dotnet run --project src/LocalServe.Cli -- backup list

# 查看数据库信息
dotnet run --project src/LocalServe.Cli -- db info
```

### 7.3 恢复流程

1. 停止服务。
2. 用最近全量备份 + WAL 恢复数据库。
3. 启动服务，运行 `PRAGMA integrity_check`。
4. 校验审计链：若备份点之后有写入，哈希链会断裂，需从归档重建后续区段。

> ⚠️ **注意**：恢复会破坏备份点之后的审计哈希链。恢复动作本身必须记录到运维审计。

### 7.4 密钥管理

| 密钥 | 用途 | 轮换周期 |
|---|---|---|
| `JWT_SECRET` | 签发/验证 JWT | 90 天（双密钥发布，旧密钥 24h 宽限期） |
| `CREDENTIAL_MASTER_KEY` | AES-256-GCM 加密敏感数据 | 180 天（重加密流程） |
| SMTP 凭证 | 邮件发送 | 90 天 |

## 8. 积分系统管理

> 积分系统为「服务端权威账本 + 客户端本地账本」双轨制。管理端负责规则配置与人工审核。

### 8.1 积分规则配置

进入管理端「积分管理」，可动态配置：

| 规则键 | 默认值 | 说明 |
|---|---|---|
| `monthly.grant` | 100 | 每月赠送积分（当月过期） |
| `daily.login` | 10 | 每日登录赠送积分 |
| `daily.login.streak_bonus` | 5 | 连续登录追加/天 |
| `project.create_cost` | 2 | 创建项目消耗积分 |
| `ai.base_cost` | 1 | AI 调用基础消耗 |
| `ai.model.<id>` | 1–5 | 各模型倍率（消耗 = base × rate） |
| `recharge.rate` | 1 | 充值比例（1 元 = N 积分） |
| `contribution.vulnerability` | 500 | 漏洞贡献奖励基准 |
| `contribution.github` | 200 | GitHub 贡献奖励 |

操作步骤：

1. 进入「积分管理」→「积分规则」。
2. 修改对应输入框数值。
3. 点击 **保存规则**（修改后立即生效，60s 规则缓存自动失效）。
4. 点击 **重置默认值** 可恢复种子值。

### 8.2 充值订单审核

1. 进入「积分管理」→「充值订单审核」。
2. 通过状态筛选（全部/待审核/已通过/已拒绝）查看订单。
3. 对 `pending` 订单点击 **通过**（发放积分）或 **拒绝**（关闭订单）。

> 权限要求：`billing.review`。通过后积分来源为 `recharge`，不设过期时间。

### 8.3 社区贡献审核

1. 进入「积分管理」→「社区贡献审核」。
2. 查看申请详情（类型：漏洞/GitHub/其他；标题、描述、证据链接）。
3. 点击 **通过** 或 **拒绝**。

> **指数级奖励**：通过后奖励 = 基准 × 2^(n-1)，n 为该用户此前已批准次数。奖励同时计入钱包积分与等级积分。

### 8.4 用户积分调整

1. 进入用户详情或通过积分管理接口。
2. 调用 `/api/admin/points/users/{userId}/adjust`，传入正/负 Delta 与原因。
3. 系统校验余额（负值余额不足拒绝），并写入审计日志。

### 8.5 积分统计

「积分管理」顶部展示统计卡片：总用户数、积分余额合计、累计发放、累计消耗、待审核充值、待审核贡献。

## 9. AI 运行时管理

### 9.1 查看运行时状态

```bash
dotnet run --project src/LocalServe.Cli -- runtime status
```

输出包含「运行时来源：内置/外部安装」与模型服务状态。

### 9.2 安装与拉取模型

```bash
# 手动获取内置运行时（下载 + 校验 + 解包）
localserve runtime install

# 拉取默认基座模型（如 qwen3:8b）
localserve runtime pull

# 拉取指定模型
localserve runtime pull qwen3:8b

# 启动模型服务（无二进制时自动安装）
localserve runtime start
```

### 9.3 管理端 API 操作

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/model-runtime/embedded` | GET | 安装快照 + 拉取任务快照 |
| `/api/model-runtime/embedded/install` | POST | 后台触发安装（admin） |
| `/api/model-runtime/pull` | POST | 拉取模型（admin） |
| `/api/model-runtime/pull/status` | GET | 拉取进度 |
| `/api/model-runtime/pull/cancel` | POST | 取消拉取（已下载层不丢失） |

### 9.4 相关环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `WTM_OLLAMA_EMBEDDED` | 1 | =0 关闭内置运行时子系统 |
| `WTM_OLLAMA_AUTO_INSTALL` | 1 | =0 禁止隐式下载 |
| `WTM_OLLAMA_URL` | — | 显式下载来源（内网镜像） |
| `WTM_OLLAMA_VERSION` | latest | 锁定版本 |
| `WTM_MODEL_HOST` | `http://127.0.0.1:11434` | 模型服务地址 |

## 10. 安全与合规

### 10.1 最小权限原则

- 角色只授必需权限，优先使用权限模板。
- 负向权限 `deny:` 慎用：优先通过角色拆分实现隔离。

### 10.2 变更留痕

- 敏感授权操作建议走审批流，自动写入审计。
- 白名单模式先在测试环境验证，避免误锁生产 IP。

### 10.3 SLA 参考

| 指标 | 目标 |
|---|---|
| 服务可用性 | 99.9%（月度） |
| 权限验证响应时间 | P95 < 200ms |
| 权限变更传播 | ≤5 分钟 |
| 并发用户 | ≥10,000 |

## 11. 常见问题

**Q：为什么用户有角色但无法访问某功能？**
A：可能被负向权限 `deny:` 覆盖，或组织作用域未包含该资源。在用户详情的「权限解析」中查看来源。

**Q：修改角色权限后多久生效？**
A：进程内缓存即时失效；外部系统通过同步水印轮询，默认 60 秒内收敛。

**Q：忘记密码怎么办？**
A：联系平台管理员重置。管理员在用户管理中选择「重置密码」。

**Q：认证器丢失，MFA 无法登录？**
A：联系管理员在「系统设置」中为用户解除 MFA 绑定，然后重新绑定。

**Q：审计日志可以删除吗？**
A：不可以。审计日志受触发器保护且哈希链校验任何篡改。

**Q：如何彻底卸载 AI 运行时？**
A：删除 `<root>/runtime/` 目录（内置运行时自包含，卸载 = 删除目录）。
